# Recent Updates - PDF Image Extractor & Namer

This log summarizes the major technical upgrades and user experience improvements implemented in the recent development cycle.

## 🚀 Key Features

### 1. Multi-Model Offline AI Engine
*   **Architectural Refactor:** The local vision service now supports multiple model architectures (Florence-2 and SmolVLM).
*   **Model Options:**
    *   **Florence-2-base-ft:** High-speed specialist for OCR and structured naming.
    *   **Granite-Docling-258M:** Highly efficient IBM/Docling vision model for document analysis and scene description (Replaced SmolVLM-256M).
    *   **SmolVLM-500M:** Advanced Instruct model for nuanced visual understanding.
*   **Hardware Acceleration:** Full WebGPU support with automatic `fp16` vs `fp32` feature detection and WASM fallback.

### 2. Offline Document Intelligence (Qwen3.5)
*   Integrates **Qwen3.5-0.8B-ONNX** as a standalone offline text generator.
*   Allows for **Fully Offline README Generation** directly from PDF text.
*   Implemented **Live Token Streaming** for real-time feedback during the generation process.

### 3. Metadata & Hover Insights
*   **Short Filenames:** Filenames are now automatically shortened to ~5 words for project cleanliness.
*   **Detailed Captions:** The full AI-generated description (1-2 sentences) is stored in the image metadata.
*   **Smart Tooltips:** Users can now hover over any image thumbnail to see the full context generated by the AI.

## 🎨 UI & UX Improvements
*   **Unified Model Banner:** A global loading indicator at the top of the app tracks both Vision and Text models simultaneously.
*   **Dynamic Reset:** Added a "New PDF" button to clear the workspace and start fresh without a full page reload.
*   **Model Selectors:** Added a model switcher in the header for real-time control over the offline brain.
*   **Streamlined Logic:** Improved rate-limiting and chunk processing for more reliable performance.

## 🛠 Technical Details
*   **Core Engine:** Upgraded to `@huggingface/transformers` v4.
*   **Quantization:** All offline models use `q4` or `q4f16` quantization for optimal browser memory usage (~250MB - 800MB depending on the model).
*   **Schema Enforcement:** Gemini (Online mode) now uses strict JSON schema response types for 100% reliable filename extraction.
